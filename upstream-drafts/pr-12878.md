Fixes #12878

## 变更说明

关闭「设置 → 编辑器 → 生成 SQL 时为标识符添加引号」后，现在**所有**生成 SQL 的面都会省略可省的引号，而不再只是新建查询一处。此前该开关只影响新建查询/DDL/补全；复制 SQL 与数据视图 SELECT 两个面各自为政：

1. **复制提取器补齐（bug 修复）**：复制 UPDATE、WHERE 条件、SELECT、以及 DELETEs/INSERTs 中 DELETE 语句的谓词，此前都无视复制配置里的「表名和字段名加引号」（UPDATE 没有引号钩子；DELETE 谓词传 `quote=None` 的手法对 Oracle/MySQL 无效，标识符仍带引号）。现在四个面与 INSERT 共用同一套引用格式化：只有方言规则证明去掉引号后仍解析到同一对象时才剥引号（Oracle 全大写、非保留字等；大小写敏感名称与保留字保留引号）。
2. **主开关联动**：编辑器全局开关成为上界——关闭时复制出的 SQL 一律不加引号；开启时保留复制配置对话框里的细调勾选（被接管时对话框会显示提示）。该勾选同时新增对「复制为 UPDATE」生效。
3. **数据视图 SELECT 接入开关**：数据 tab 的分页/筛选/排序 SQL 与底部状态栏「当前页 SQL」遵循同一开关。内部机制列（`__DBX_ROWID`、大值预览 marker）不满足安全剥引号规则，永远保持引号，列匹配不受影响；开关默认开启，旧版 agent 不认识新字段时行为不变（serde 默认值兜底）。

以 Oracle 11g 实测（无主键基表，ROWID 路径）：

**Before**
```sql
SELECT "__DBX_ROWID", "REQUEST_ID", "REQUEST_TIME", … FROM (SELECT ROWIDTOCHAR(t.ROWID) AS "__DBX_ROWID", t.* FROM "MESPRD"."API_REQUEST_RESPONSE" t) WHERE ROWNUM <= 100
```

**After**
```sql
SELECT "__DBX_ROWID", REQUEST_ID, REQUEST_TIME, … FROM (SELECT ROWIDTOCHAR(t.ROWID) AS "__DBX_ROWID", t.* FROM MESPRD.API_REQUEST_RESPONSE t) WHERE ROWNUM <= 100
```

## 变更类型

- [x] Bug 修复（复制 UPDATE/WHERE/SELECT 与 DELETE 谓词不读引号开关；DELETE `quote=None` 对 Oracle/MySQL 无效）
- [x] 功能增强（数据视图 SQL 与排序引用接入全局开关；主开关与复制细调联动）

- 数据 tab 七处 `buildTableSelectSql` 调用点透传开关；排序引用（点列头/结构化排序/打开时默认排序）按需加引号
