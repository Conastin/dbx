## 变更说明 / Change Description

Oracle 数据 tab 打开含 CLOB/NCLOB/BLOB 的表时会全量加载每个 LOB 值，大 LOB 表打开缓慢甚至加载失败（本地构建的测试表约 7.5 万行、CLOB 总量约 333 MB，"加载全部"意味着全量传输）。本 PR 在生成的表数据 SQL 中为 LOB 列加上界，复用 MySQL/PostgreSQL/DB2 数据 tab 既有的有界预览机制：

- **SQL 层预览**：CLOB/NCLOB 投影为 `DBMS_LOB.SUBSTR(col, N+1, 1)`，BLOB 投影为 `'0x' || RAWTOHEX(DBMS_LOB.SUBSTR(...))`，并各配一列 marker 携带 `'T:N:' || DBMS_LOB.GETLENGTH(col)` 总大小。取数长度按 SQL 类型上限钳制（VARCHAR2 4000 字节 → 999 字符；RAW 2000 字节 → 1998 字节），不受客户端预览预算影响。
- **分页**：ROWORD 分页外层按别名重选内联视图，预览与 marker 列在第 2 页起仍然保留；无主键表（ROWID 合成键）的 marker 下标按结果集位置编号，与客户端剥离逻辑的校验一致。
- **点开取全值**：双击 / 单元格详情 / 复制 / "加载当前页完整文本" 走既有的按键回查取回完整值——无主键基表用合成 `__DBX_ROWID`，有主键用主键。
- **Agent**：SQL 已含预览 marker 时 Oracle agent 跳过 `deferLobs`，保证嵌套值改写（几何 → WKT、XMLType → XMLSERIALIZE、不透明对象占位）照常执行；查询 tab 的 deferral 不受影响。
- **元数据**：Oracle 加入"打开表前先等列元数据"的引擎集合（打开路径，及恢复 tab 的 reload 路径），避免空列清单生成无截断的 `SELECT *`。
- XMLTYPE/BFILE/LONG/对象列、无键视图、无 LOB 列的表保持原有行为。

行为说明：底栏仍显示简化的用户可见 SQL（既有机制，含 marker 的执行 SQL 会重建为无预览投影的版本，与 MySQL/PostgreSQL/DB2 一致）；按需取全值无字节上限（与其他引擎一致）；32 MB `maxResultBytes` 仍仅 MySQL 连接池生效——Oracle 的界来自每格截断本身（每页 LOB 单元格 ≤ 999 字符）。

**实测**（构建的测试表：3 个 CLOB 列、约 7.5 万行，Oracle 11.2，同一客户端/连接交错执行两轮；页内 CLOB 平均约 2–5k 字符）：

| 投影 | 100 行页 | 1000 行窗口 |
|---|---|---|
| 改前（全量 LOB） | 78 / 88 ms | 189 / 239 ms |
| 改后（SUBSTR 预览） | 60 / 67 ms | 95 / 99 ms |

最新 100 行的传输内容量从 533,738 字符降到 90,741 字符（约 17%）；改前"加载全部"需传输 332.7 MB 的 CLOB，这正是"有时候加载不出来"的根源。
